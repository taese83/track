# Performance Budget — 완화·대조군

## 3. 완화 수단과 대가 — 적용 순서

시각 손실이 없는 수단을 먼저 소진하고, 마지막 수단만 사용자에게 고지한다.

1. **Frustum culling** (손실 없음, 배지 불필요, 등급 무관 상시 적용) — 화면 밖 피스는 애초에
   보이지 않으므로 정직성 배지 대상이 아니다.
2. **동일 지오메트리 인스턴싱** (손실 없음, 배지 불필요) — 같은 클래스·파라미터의 Str1/Cor1을
   `InstancedMesh`로 묶어 draw call만 줄인다. 피스 단위 로컬 프레임 설계(tech-stack)와 충돌하지
   않는다 — 트랜스폼만 개별, 지오메트리 버퍼만 공유.
3. **거리 기반 LOD** (시각 손실 있음 — 원거리 피스 폴리곤 축소, 플라이스루 중 근접 시 원복) —
   300+ 등급에서만 활성화, "대형 트랙: 일부 최적화 적용" 배지 노출.
4. **세그먼트 분할 수 축소** (최후 수단, 시각 손실 큼) — S곡선/로그곡선의 곡면 분할 수를 줄인다.
   단, REQ-F-002의 이음매 접선각 오차 허용치(±1°) 아래로는 축소할 수 없다 — 이 하한을 넘기면
   완화가 아니라 형상 결함(REQ-F-001/002 위반)이므로 금지. 배지 노출 필수.

**트랙 벽(FEAT-020)은 완화 수단 목록에 넣지 않는다.** 벽을 끄면 형상이 "레인이 그려진 판"으로
돌아가 REQ-F-025가 요구한 것 자체가 사라진다 — 그것은 화질 저하가 아니라 기능 제거다. 벽은 레인
면과 같은 표본을 쓰므로 4단계(세그먼트 분할 수 축소)가 적용되면 벽의 표본도 함께 줄어든다.
따로 끄는 스위치를 두지 않는다.

배지 고지 여부는 3·4가 실제로 적용됐을 때만 필요하다(1·2는 사용자가 지각할 수 있는 화질
변화가 없으므로 REQ-F-013의 "조용히 넘기지 않는다" 대상이 아니다).


## 4. 대조군 정의 (TC-011-2)

완화 적용 대비 개선을 검증하려면 완화를 끈 상태를 재현 가능해야 한다. `?perfDebug=raw`
URL 쿼리 파라미터로 완화 상태 머신을 강제 비활성화한다(프로덕션 UI에는 노출하지 않는
개발/테스트 전용 스위치, 300+ 트랙에서도 3단계 LOD·4단계 분할 축소를 끈 채 렌더). Playwright가
동일 300+ fixture를 `?perfDebug=raw` 유/무 두 번 로드해 `flythroughFps`를 비교하고, 완화 적용
쪽이 개선됐는지 어서션한다. 이 스위치 자체가 §2의 피스 수 게이트를 우회하는 것은 아니다 —
게이트 평가는 그대로 일어나되 실제 완화 로직만 no-op 처리한다.

# Layout Spec — 상태별 레이아웃

## 상태별 레이아웃

### 입력 대기
- header + 중앙 카드(단일 컬럼, 목록/스트립/alert 슬롯 없음): 입력창(48px, 좌우 패딩 16px, 인풋
  기준 spacing-layout 원칙), placeholder 예시, 안내 문구. Primary 액션은 "붙여넣기" 인풋 자체.

### 로딩
- 3분할 셸 그대로, 목록·스트립은 스켈레톤. 캔버스 자리에 중앙 스피너 + 진행 문구.
  ASSUMPTION-007 임계값 초과 시 같은 자리에 "시간이 걸리고 있어요" 텍스트 추가(레이아웃 불변).

### 3D 표시 (주 상태)
- 목록: `RestoredPath` 순서대로 132행, 각 행 = 구간유형 아이콘 + 라벨 + (해당 시) 근거배지 +
  (해당 시) "미지원: {타입명}". 현재 카메라 위치 행은 배경색으로 강조(공용 배경 신호,
  spacing-layout §Gestalt).
- 캔버스: 3D 씬 + 좌상단 오버레이(회전/줌 힌트, 1회성 → 이후 접힘) + 근거등급 범례(접이식,
  기본 접힘). 오버레이는 캔버스 내부 absolute 배치라 셸 치수에 영향 없음.
  **현재 구간 하이라이트**(FEAT-019): 공유 커서가 가리키는 구간에 `primary` 반투명 면 + 윤곽선.
  씬 안의 3D 요소이므로 셸·DOM 레이아웃에 영향이 없다(CLS 대상 아님, performance-budget §1).
  추종 시점 중에는 렌더하지 않는다.
- 스트립: 거리축 고저 곡선, 세그먼트 경계 구분선, 현재 위치 인디케이터. 클릭/드래그 → 캔버스·목록
  동기 이동(FEAT-007 구독). y축 라벨은 "상대 스케일(실측 아님)"로 고정.
- 세 표면의 "현재 구간" 인덱스는 단일 상태로 upward 관리(예: `useTrackCursor()`) — 목록 클릭,
  스트립 스크럽, 캔버스 자유 오빗 이탈 시 서로 다른 소스가 같은 상태를 갱신한다.

### 부분 실패 (비폐곡선)
- 3D 표시와 동일 셸. alert 슬롯에 상시 배너 텍스트 노출(고정 40px, §1). 실패 구간 이후 목록 행은
  회색 배경 + 아이콘, 스트립 해당 구간은 회색·점선이며 클릭 비활성. 캔버스는 복원 구간까지만 렌더.

### 완전 실패
- 입력 대기와 같은 중앙 카드 레이아웃. alert 슬롯은 `role="alert" aria-live="assertive"`로 즉시
  통지(입력 대기 상태에 없던 슬롯이 여기서 재사용됨). 원인별 문구 + 재시도 버튼(1개, primary).
  파싱 실패 시 카드 하단에 접이식 디버그 영역 추가(원본 응답 일부).

### WebGL 미지원
- 목록 컬럼이 폭을 100%로 확장하고 캔버스 컬럼은 렌더되지 않는다(스트립은 유지 — 고도 데이터는
  파싱됐으므로 그래프 자체는 2D로 그릴 수 있다). 목록은 기본 펼침(토글 없음), alert 슬롯에 안내
  배너 상시 노출. 이 컬럼 폭 변화는 §1의 "흔들림 금지" 대상이 아니다(별개 상태로의 최초 진입, 이후
  동일 상태 내에서는 고정).


## Chart(프로파일 스트립) 리사이즈 계약

- 최소 폭 320px, 최소 높이 96px(그 이하로는 스트립을 숨기고 "구간 목록에서 확인" 링크로 대체 —
  완전 hidden 아님, 대체 진입점 유지).
- 데스크톱에서 스트립 collapse(접힘) 시에도 높이 40px 헤더 바(현재 위치 텍스트 요약: "슬로프 상승
  중, 12/132")는 유지 — 완전 숨김 금지(FEAT-007의 유일한 조작 표면이 사라지면 안 됨).
- 모바일 요약 대체: 표(distance-agnostic) 대신 "현재 구간 카드"(유형·등급배지만) 1개로 축소.

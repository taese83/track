# Piece Geometry — 피스 끝점 카탈로그 (구현 정본)

FEAT-002가 `ParsedPiece.vertex1/vertex2`를 산출하는 데 필요한 **로컬 끝점 오프셋 23종**이다.
`00_source/track-editor-data-model.md`의 피스 카탈로그(`w`/`h`/`l`/`colors`)는 끝점 오프셋을
담지 않고, 실측 수치는 그동안 `02_design/preview/store.js`에만 있었다. Phase 3은 preview
HTML/CSS/JS를 구현 입력으로 전달하는 것을 금지하므로(`phase-3-development.md`), 그 수치를
구현이 참조할 수 있는 정본 위치로 **승격**한다. 값은 원본 그대로이며 새 결정을 만들지 않는다.

## 좌표 계약

편집기 `viewer.js`의 `Sprite.prototype.getVertex1 = position.clone().add(rvertex1)`.
즉 **끝점(절대) = position + rotate(vertex, angleDeg)** 이고, 회전은 **원점 기준**이며
`position` 가산은 회전 **뒤**다. 순서를 바꾸면 좌표가 어긋난다.

```
rotate([x, y], deg) = [x·cos θ − y·sin θ,  x·sin θ + y·cos θ],  θ = deg × π / 180
vertex1_abs = { x: piece.x + rotate(v1, angleDeg).x,  y: piece.y + rotate(v1, angleDeg).y }
vertex2_abs = { x: piece.x + rotate(v2, angleDeg).x,  y: piece.y + rotate(v2, angleDeg).y }
```

### 단위: 1 px = 1 cm (PC-008, B-001 닫힘)

단위는 편집기 px이고 **1 px = 1 cm**다. 종전 이 문서는 "실물 cm 환산 미해결"이라고 적고
있었으나 그 사이 B-001이 닫혔는데 정정이 도달하지 않았다(2026-08-30 발견) — 아래 §레인
기하가 이미 12 cm·36 cm를 쓰고 있었으므로 **문서가 자기모순 상태**였다.

닫힌 근거(PC-008, 픽셀 측정):

| 확인 | 결과 |
|---|---|
| 레인 3개 · 레인 폭 12 px | 픽셀 분석으로 확정 |
| `l` = 레인수 × 레인길이 | 직선 6종 **전부** 일치 |
| 타미야 실물 코스폭 11.5 cm | 12 cm와 4% 이내 |

그러므로 이 문서의 모든 px 수치는 그대로 cm로 읽는다. 별도 스케일 계수를 두지 않는다.

`vertex2`가 **local +x 쪽**이며 START(`Str2`)에서 화살표가 가리키는 방향이다(FEAT-003 D-038 ①).

### 통과 방향 — 피스의 절반 이상이 역방향이다 (PC-009)

복원된 경로에서 피스는 `vertex1→vertex2` 방향으로만 지나가지 않는다. 참조 트랙 실측:
**정방향 30 · 역방향 99 · 미매칭 2.** 이음새 거리는 네 조합 모두 0이었다 — 기하는 처음부터
정확했고 빠진 것은 **방향 정보뿐**이었다.

그래서 `restoreOrder`는 각 피스에 **어느 끝으로 진입하는가**(`flipped`)를 기록해 하류로
넘겨야 한다. 이 값을 버리면 역방향 피스에 고도가 거꾸로 깔려 **높은 쪽 끝이 반대편에
붙는다.** 평지는 `dz=0`이라 증상이 없고 슬로프만 통째로 뒤집혀 "슬로프만 트랙에서 떨어져
나온" 것처럼 보인다(실측: 이음새 131곳 중 101곳이 벌어졌다가, 방향을 되살리자 7곳).

**함정 — 끝점을 맞바꾸지 마라.** `flipped`일 때 `vertex1`/`vertex2`를 교환하면 코너 원호의
중심이 현의 수직이등분선 **반대편**으로 넘어가 원호가 거울상이 된다. 형상은 정방향으로
생성한 뒤 **표본 배열만 뒤집는다**(구현: `elevation/piece-path.ts`의 `forward`).

### 코너는 원호로 샘플링한다 (PC-008)

코너 피스의 내부 경로는 현이 아니라 원호다.

```
R = chord / (2 · sin(turn / 2))     // turn = 선회각(현 각도의 2배)
```

실측: `Cor1`의 중점이 현에서 **4.11 cm** 벗어난다(직선이면 0). 이 값은 형상을 바꾸지 않는
수정(통과 방향 복원 등) 앞뒤로 **불변이어야** 하므로 회귀 단언으로 쓸 수 있다.

## compat 위치 보정 (REQ-F-021)

> `compat` — 트랙 저장 시점 버전이 `COMPATIBILITY_ID`(26586)보다 오래됐는지. **true이면 `Cor1`의

**티켓만 읽고 개발하면 아래를 하나도 모른다.** Phase 3은 preview 코드를 구현 입력으로
전달하는 것을 금지하므로 정본 위치로 승격한다. 값은 원본 그대로이며 새 결정을 만들지 않는다.

### 레인은 선이 아니라 면이다 (D-034)

| 항목 | 값 |
|---|---|
| 레인 수 | **3** |
| 레인 폭 | **12 cm** (각각) |
| 전체 트랙 폭 | **36 cm** = 3 × 12 |
| 레인 중심 가로 위치 | `[−12, 0, +12]` cm |
| 인접 레인 사이 틈 | **0** — 빈틈 없이 맞붙는다 |

레인마다 좌·우 **가장자리**를 함께 만든다(`bands[L] = [lo, hi]`). 가장자리는 중심선과
**같은 규칙**(웨이브 활 · 레인체인지 자리바꿈 · 평면 고도)으로 생성되므로, 레인체인지
구간에서 레인 **면 전체**가 자리를 옮긴다.

렌더 단위: 레인 면 3개 + 경계선 4줄. 참조 트랙(132피스) 실측 = 면 396개 · 경계선 528개.

**결함 이력(반드시 읽을 것)**: 트랙 면을 바깥 레인 두 개의 **중심선**으로 만들면 폭이
24cm가 된다(2 × 12) — 양쪽 바깥 반 레인 6cm씩이 통째로 빠진다. 상수는 36cm인데 렌더는
24cm인 채로 화면에 "3레인 폭 36cm"라고 표기하고 있었다. **화면으로는 둘 다 그럴듯해
보이고 숫자로만 드러난다** — `TRACK_WIDTH` 상수와 실제 렌더 폭을 대조하는 단언을 둔다.

### 레인체인지는 한 칸씩 순환한다 (D-033)

`Lan1`(162 cm) 구간에서 세 레인이 한 칸씩 순환한다 — **레인0→1, 레인1→2, 레인2→0**.
바깥으로 밀려난 레인2가 나머지 둘을 **가로지르며** 반대편으로 넘어가는 것이 교차 형상이다.

자리바꿈은 **피스 전 구간에 걸친 완만한 S곡선이 아니다**(D-036 ②, 프리뷰에서 사용자와
확정). 가운데 **45% 구간에서만 직선으로** 건너가고 앞뒤는 직선으로 남으며 **양 끝에서
각지게 꺾인다** — 실제 레인체인지 피스가 그렇게 생겼다.

```
span = 0.45
u    = clamp((t − (1 − span)/2) / span, 0, 1)
swap = shift × u
```

**고도 변화는 없다**(수평축 변형이다). `(1 − cos πt)/2` S곡선으로 적혀 있던 것은
2026-08-30에 정정했다 — 프리뷰 확정이 정본에 도달하지 않은 채였다.

근거는 공식 API다: `"changers": 1, "order": [1,2,3]`. changer 하나로 `[1,2,3]`이 나오려면
레인을 한 칸씩 밀어야 한다 — 좌우 대칭 교환(0↔2, 1 고정)이면 두 바퀴 만에 원위치라 세
레인을 다 돌 수 없다.

| 실측(WS67Y2) | 값 |
|---|---|
| 가로 위치 전이 | `[−12, 0, +12]` → `[0, +12, −12]` cm |
| 위치 집합 보존 | 세 자리가 그대로 채워진다 |
| 교차 횟수 | lane1×lane2 1회 · lane0×lane2 1회 · lane0×lane1 0회 |
| 길이 | 162.0 cm |

**측정 주의**: 가로 위치의 기준선을 **움직이는 레인**으로 잡으면 그 레인의 이동량이 항상
0으로 나온다. 기준은 피스의 원래 진행축(`p1`→`p2`)이다.

### 두 칸 건너뛰는 레인은 육교다 (D-035)

순환에서 트랙 폭을 두 칸 건너뛰는 레인(**3→1**)은 나머지 둘 **위로** 넘어간다 — 같은
높이로 지나가면 서로 통과해 버린다.

| 항목 | 값 |
|---|---|
| 높이 | **+8 cm** |
| 모양 | `sin²(πu)` — `u`는 **자리바꿈 구간의 로컬 파라미터**(위 §순환의 `u`)지 피스 전체 `t`가 아니다. 육교는 자리바꿈이 일어나는 그 구간에서만 넘어간다(D-036 ③) |
| 판별 | 색·이름이 아니라 **이동 폭**: `|shift| > 레인 폭`이면 육교다 |
| 나머지 두 레인(1→2, 2→3) | 고도 변화 없음 |

### 이음새는 하나의 공통 절단선으로 자른다 (D-036 ④)

실제 트랙 피스는 진행 방향에 수직인 직선으로 잘려 맞물린다. 그래서 코너에서는 **바깥쪽
가장자리가 더 길고 안쪽이 더 짧다** — 같은 절단선에 닿으려면 반지름이 큰 바깥이 더 멀리
나가야 하기 때문이다.

피스마다 자기 끝점의 법선으로 폭을 만들면 두 피스의 절단선이 몇 도씩 어긋나 **바깥쪽에
삼각 노치**가 생긴다. 양쪽 가장자리를 공통 절단선 위로 옮겨 없앤다.

**중심선 연속만으로는 부족하다.** 현재 구현은 중심선 이음새(`scene-layout`)만 검증한다 —
레인을 **면**으로 그리기 시작하는 순간 이 조항이 필요해진다.

### 레인 구분에 SVG filter를 쓰지 않는다 (D-036 ⑤)

SVG `filter`는 도형을 별도 래스터화해 **가장자리에 얇은 검은 실선**을 남긴다. 가운데 레인을
밝게 하려면 filter가 아니라 **색으로** 구분한다.

### 코너 꺾임은 끝점을 고정하고 가운데만 부푼다 (D-036 ①)

선회각을 키우면 원호 반지름이 작아져 더 급하게 꺾이지만 **끝점은 그대로**이고 가운데가 더
부풀 뿐이라 이음새는 벌어지지 않는다. 구현은 이미 이 조항을 따른다(`piece-path.ts`).

### 웨이브 (D-032, 참고)

웨이브(`Chi*`)는 고도 변화가 없고 진행 방향 기준 **왼쪽으로 5 cm 곡면 돌출**하며 양 끝이
직선이다. 레인 가장자리도 같은 활을 따른다.

쓰며 순환도 한 칸이다: 주행 레인 j ← 경로 (4 − j) mod 3 역방향.

공식 미확인, 실측 정본 유지(ASSUMPTION). `Lan3`(burning changer)은 같은 장치로 그릴 수 있으나
도면 실측 전이다(NEEDS_DECISION).

# Design System — 토큰(색·타이포·간격·모드)

## 0. 방향 커밋과 기각 기록

- **커밋한 방향**: 계측기(instrument) 톤 — 다크 캔버스 기본, 무채색 90% + 데이터 색만 유채색, 장식 0. 근거: 이 화면은 관람이 아니라 판단 근거이고 3D 캔버스가 주인공이다(ux-brief Density·Reference mood).
- **기각한 방향**: 라이트 기본 "도면 앱" 톤 — 편집기와 배경까지 맞추는 안. 기각 이유: 3D 고저차 형상 대비가 어두운 배경에서 더 크고(project-brief Open Decision의 다크 제안 채택), 대조는 배경이 아니라 **피스 색 일치**로 이미 성립한다. 라이트는 보조 모드로 유지.
- 스타일 타일 후보 비교는 사용자 opt-in 미요청으로 생략하고 단일 시안으로 수렴했다(발산 축·기각 기록은 위 2줄).
- 다크 기본은 Open Decision("3D 뷰 기본 배경")에 대한 **잠정 확정값**이다 — 기능 영향 없어 임시값 진행 가능(project-brief).


## 1. 색 결정 — 상승/하강은 원본 편집기 색을 쓴다

**결정: 상승 = 원본 빨강 `#AD0A09`(rgb 173,10,9), 하강 = 원본 파랑 `#004E8F`(rgb 0,78,143).**
ux-brief가 제안한 초록/주황은 **기각**한다 — 근거 기록이 없고, 사용자 1순위 성공 조건이 "도면과 3D 나란히 대조"이므로 3D 팔레트가 원본(measured, 픽셀 실측 2026-08-28)과 다르면 대조 자체가 깨진다. 초록/주황은 편집기 팔레트의 다른 인덱스(청록 c0, 주황 c6)와도 충돌한다.

- **표면 분리 계약**: `rise/fall` 원본색은 3D 피스 표면·프로파일 스트립 채움에만 쓴다. 다크 배경 위 텍스트/아이콘/보더에는 같은 hue의 밝은 파생 토큰(`-fg`)을 쓴다 — 원본 `#AD0A09`는 다크 배경 대비 ≈2.5:1로 비텍스트 3:1 미달이기 때문.
- **error(빨강)와 rise(빨강) 충돌**: error는 배너/필드 등 UI 크롬에서만, rise는 기하·스트립에서만 나타나고 양쪽 모두 아이콘+텍스트 병행이 필수라 표면·인코딩 양쪽에서 분리된다.
- **3중 인코딩(REQ-NFR-003, 협상 불가)**: 상승/하강은 항상 색 + 형태(↑/↓ 화살표, 뱅크 기울인 사각형, 레인체인지 갈래) + 텍스트("상승 5%"). 토큰은 색·아이콘 전경색·텍스트색을 모두 제공하며, 색 단독 사용은 design-reviewer 거부 사유다.
- 라이트 모드에서는 원본색을 그대로 텍스트에도 쓸 수 있다 — 흰 배경 대비 `#AD0A09` ≈7.3:1, `#004E8F` ≈8.4:1 (AA 통과, 원본색 채택의 추가 근거).

### 근거 등급 배지 (REQ-F-013 — 4단계, 상시 노출)

색은 2차 채널이다 — **1차 채널은 텍스트 라벨, 2차는 보더 형태, 3차가 색**. 4등급 전부 유채색이면 rise/fall·트랙 팔레트와 충돌하므로 양끝만 유채색으로 한다. 배지는 `bg-surface` 위 12px 텍스트 + 1px 보더의 저소음 형태로 3D를 가리지 않는다.

| 등급 | text/border (다크) | 보더 형태 | 근거 |
|---|---|---|---|
| measured | `#7EE2A8` | 실선 | 검증된 사실 = green 관례 |
| confirmed | `#C9CED6` | 실선 | 유채색 예산 절약, 밝은 무채로 신뢰 표현 |
| inferred | `#F5C15C` | 실선 | 추정 = amber(warning 인접) 관례 |
| unknown | `#9AA1AA` | **점선** | 최저 등급은 색+형태 이중 구분(fail-segment 점선과 동일 문법) |


## 3. 타이포그래피

- 폰트 스택: `system-ui, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif` — **웹폰트 미사용**. 근거: 판독 도구 + 번들 예산(REQ-NFR-001), 원칙의 "UI 전용 도구는 system-ui 충분".
- 스케일(1.2 비율, 4px 격자): H1 20/1.3/600(패널·상태 제목) · body 16/1.5/400(안내문·에러 문구) · data 14/1.45/400(구간 목록·스트립 라벨 — 데이터 밀집+짧은 라벨+스캔 3조건 충족) · caption 12/1.35/400(배지·단위, +0.02em). 11px 미만 금지.
- 숫자(각도·거리·피스 수)는 `font-variant-numeric: tabular-nums` + 우측 정렬 — 구간 목록 표의 자릿수 비교 전제.
- 한글 letter-spacing 0(양수 금지). 텍스트 위계는 색 3단계(`text-primary/secondary/disabled`)로.


## 4. 간격·radius·그림자·모션

- **간격**: 4px 기반 `--spacing: .25rem`. 사용 단계 4/8/12/16/24/32. 오버레이 패널 내부 패딩 12~16px(밀도 낮음~중간).
- **radius**: 6px 기본(패널·버튼·입력) / 4px(배지) / 9999(pill 마커). 계측기 톤이므로 큰 라운드 금지.
- **elevation**: 그림자 대신 표면 밝기 3계층(canvas→surface→raised) + 1px `border`. 라이트 모드만 `shadow-sm` 허용.
- **캔버스 오버레이 계약**: 3D 위에 뜨는 모든 패널(프로파일 스트립·배지·배너)은 배경 불투명도 ≥ 0.88 — 씬 색과 텍스트 충돌 방지. 대비 계산은 합성 후 색 기준.
- **모션 토큰**(선언 목적 명시): `--duration-fast: 120ms` — hover/포커스 등 인터랙션 전환 전용 · `--duration-base: 200ms` — 패널 개폐/배너 등장 전용. 카메라 이동·자동재생은 3D 코드 소관이며 이 토큰을 쓰지 않는다(루프/공간 애니메이션 금지 용도). `prefers-reduced-motion`: 두 토큰 0ms + 자동재생 자동 진입 금지 + 카메라 전환 즉시 컷.


## 5. 다크/라이트/강제 색

- 다크가 기본(`:root`), 라이트는 `.light`에서 neutral 반전 + rise/fall은 **원본색 그대로**(§1 대비 근거) + semantic은 600 계열(`#DC2626/#D97706/#16A34A/#2563EB`)로 교체.
- `forced-colors: active`: 배지 보더·실패 점선·포커스 링은 `CanvasText`/`Highlight` 시스템 색으로 승계, 3D 캔버스는 예외 표면임을 안내문으로 보완.

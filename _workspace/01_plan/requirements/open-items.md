# Requirements — 미결

## Assumptions
- ~~ASSUMPTION-001 슬로프 낙차 11cm~~ — **폐기(D-022).** 고도를 실물 낙차가 아니라 현(chord) 각도 렌더 규칙으로 정하기로 사용자가 확정했으므로 이 가정은 더 이상 쓰이지 않는다. 실물 낙차와의 괴리(4.1~12.4배, 3차 리뷰 F1)는 알고 채택한 것이며 REQ-F-013 배지로 고지한다.
- ASSUMPTION-002 [RESOLVED — 사용자 확정 2026-08-29, D-029+D-031] 뱅크 구간 전체가 **하나의 20° 기운 평면**이며 **아래로 파인다**. 실측: 평면 적합 잔차 0.0000cm, 기울기 20.00°, z 0→−34.2→0, 최종 누적 z 0(폐합).
- **BLOCKER-002 다단 뱅크 기하 미구현(D-030)** — 뱅크 기울기 누적(+20°/−20°)은 계산하지만, 기울기가 다른 구간을 잇는 기하가 없어 상승 뱅크 2연속이 40°가 아니라 20° 평면 하나로 나온다(합성 데이터로 확인). 참조 트랙 WS67Y2는 뱅크가 교대라 이 경우가 없어 실데이터 검증이 불가능하다. 해소: 다단 뱅크가 있는 트랙 확보 후 구간별 평면을 잇도록 구현.
- ASSUMPTION-008 [소멸 — D-026] 뱅크 롤의 부호. 뱅크의 20°가 롤이 아니라 진행 방향 경사로 확정되면서 롤 자체가 없어졌다.
- ASSUMPTION-003 편집기 l(1.62m) 단일 레인 vs 3레인 합 — 트랙 전체 폭 치수에 영향. 검증: 참조 트랙 렌더 폭을 레귤러 코스 실측 폭과 비교하거나 편집기 소스 확인.
- ASSUMPTION-004 [RESOLVED — measured, 픽셀 측정 2026-08-28] 색 c=2/c=3 상승/하강 매핑 — 고도
  변화 피스(Bri*·Ban*)에 한해 `c=3`(빨강)=상승, `c=2`(파랑)=하강으로 해소됨(REQ-F-002 참조). 원래
  계획했던 "상승5/하강5, 2/2 대칭 분포로 역추정" 방식은 대칭 분포만으로는 두 매핑 후보를 통계적으로
  구분할 수 없어 원리적으로 판별 불가였다 — 실제 픽셀 RGB 측정으로만 닫혔다.
- ASSUMPTION-005 사용자가 언급하지 않은 피스(Chi* 웨이브 등)의 지오메트리 구현 수준 — REQ-F-008(플레이스홀더)이 최소 방침. 실제 곡면 구현 여부는 후속 논의.
- ASSUMPTION-006 대형 트랙 임계값 300피스로 통일(잠정) — 참조 트랙(132)~300 사이는 경계 구간으로
  REQ-F-012에서 별도 정의한다. 검증: 실사용자 트랙 샘플 수집 후 재조정.
- ASSUMPTION-007 편집기 응답 지연→loading 전환 임계값(초), 잠정치이며 미확정 — 문서 어디에서도 확정값으로
  단정하지 않는다(R4). 검증: 실측 응답시간 분포 확보 후 확정.


## Blockers
- BLOCKER-001 공개 배포 시 사이트 운영자 사전고지 미해소 — robots.txt에 금지 규칙이 없고 사용자 행동당 1건 fetch로 크롤링이 아님을 확인했으나((decision-log A-001), (decision-log D-002)), 광고로 운영되는 개인 사이트 운영자에게 사전 고지·동의를 받지 않았다. 로컬/소규모 사용 전제로는 MVP 진행 가능하나, **공개 서비스로 배포하기 전에는 반드시 재판단**해야 한다. 완화 수단인 REQ-F-019(외부 편집기 접근 계약 준수)를 Must로 승격했다 — defer 가능 등급에 두지 않는다. 사유: 공개 배포 시 소스 운영자 동의 범위 미확인.

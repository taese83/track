# Requirements — 기능 요구

## Functional Requirements

### Must Have (MVP)
- [ ] REQ-F-001 도면과 일치하는 트랙 형상(360도 회전·확대축소)
  - Given 공유 링크의 트랙 데이터 파싱이 완료된 상태, When 3D 뷰가 로드되면, Then 각 피스가 데이터의 x,y,각도에 대응하는 위치·방향으로 배치되고 드래그 회전·휠/핀치 확대축소가 즉시 반영된다.
  - 검증(수치 어서션, R2 준수): 참조 트랙(WS67Y2) 렌더 결과의 각 피스 3D 배치 좌표를 편집기 2D 도면 좌표와
    **상대 좌표 비교**로 대조한다 — 트랙 전체 bounding box 대각선 길이를 1로 정규화한 상대 좌표계에서
    각 피스 중심점 오차가 허용치(예: ±0.5%, tech-advisor 확정) 이내인지 스크립트로 어서션한다.
    육안 대조가 아니며 절대 길이 단위는 사용하지 않는다(R2).
- [ ] REQ-F-002 슬로프·뱅크 높이의 입체 표현
  - Given Bri*(슬로프) 또는 Ban*(뱅크) 피스 포함, When 해당 구간을 3D 뷰에서 보면, Then 슬로프는 S곡선(h(x)=H/2·(1−cos(πx/L)), 양끝 기울기 0°) 뱅크는 단조 상승 로그 곡선으로 렌더되어 평면 램프 꺾임 없이 앞뒤 평지/직선과 이어진다.
  - 색 규칙(measured, 픽셀 측정 2026-08-28): **고도 변화 피스(Bri*·Ban*)에 한해** 팔레트 인덱스
    `c=3`(빨강, RGB 173,10,9)은 상승, `c=2`(파랑, RGB 0,78,143)는 하강을 의미한다. `c`는 팔레트
    인덱스이지 상승/하강을 나타내는 전용 플래그가 아니므로, Bri*/Ban* 이외 피스 타입에는 이 매핑을
    적용하지 않는다(Str1의 c=5 처리는 REQ-F-020 참조).
  - 검증(수치 어서션): 참조 트랙의 Bri1×10(상승5/하강5), Ban1×4(2/2 대칭) 구간에서 이음매 지점의
    접선각 차이가 허용 오차(예: ±1°, tech-advisor 확정) 이내인지 스크립트로 확인하고, 각 구간의
    c값-방향 매핑이 위 규칙과 일치하는지 대조한다(목측 아님).
- [ ] REQ-F-003 트랙을 따라가는 시점(플라이스루)
  - Given 피스 순서가 결정적으로 복원된 트랙, When 사용자가 '트랙 따라가기'를 켜면, Then 카메라가 START(Str2) 지점에서 화살표 방향을 따라 순서대로 이동하며 고저차 통과를 확인할 수 있다.
  - 검증: 참조 트랙에서 플라이스루 시작~종료까지 132피스를 이탈 없이 통과.
- [ ] REQ-F-004 레인체인지 표현
  - Given Lan*(레인체인지) 피스 포함, When 3D 뷰 또는 플라이스루가 해당 구간에 도달하면, Then 레인 좌우 이동이 시각적으로 구분되어 표현된다.
  - 검증: 참조 트랙 Lan1×1 구간에서 레인 오프셋이 인접 직선 구간과 다르게 렌더되는지 확인.
- [ ] REQ-F-005 URL 입력 및 서버사이드 fetch/파싱
  - Given 사용자가 view/XXXXXX 형식 링크를 입력, When 제출하면, Then serverless function이 편집기에서 데이터를 가져와 파싱을 시도하고 성공/실패 결과를 화면에 반영한다.
  - 검증: 유효 링크 1건, 무효 링크 1건으로 각각 성공/에러 경로 재현.
- [ ] REQ-F-006 진행 순서의 결정적 복원
  - Given 순서 없는 피스 배치 데이터("클래스;x;y;각도;색" # 연결), When vertex1/vertex2 끝점을 매칭하면, Then 동일 입력에 대해 항상 동일한 순서가 산출된다.
  - 검증: 동일 트랙 코드로 3회 반복 조회해 피스 순서 배열이 일치하는지 비교.
- [ ] REQ-F-007 폐곡선이 아닌/미완성 트랙 처리
  - Given 끝점이 맞지 않아 폐곡선을 이루지 못하는 트랙, When 파싱이 완료되면, Then 연결 가능한 구간은 정상 렌더하고 끊긴 지점은 시각적 경고(강조색/아이콘)와 안내 텍스트로 표시하며 렌더링을 중단하지 않는다.
  - 검증: 의도적으로 끝점을 어긋나게 만든 테스트 데이터로 경고 표시 발생 확인.
- [ ] REQ-F-008 미지원 피스 타입의 가시적 표시
  - Given 23종 정의 밖 또는 미구현 피스 타입 포함, When 해당 피스를 만나면, Then 위치에 플레이스홀더(와이어프레임 박스 등)와 "미지원: {타입명}" 라벨을 노출하고 조용히 생략하지 않는다.
  - 검증: 미지원 타입을 주입한 테스트 데이터로 라벨 노출 확인.
- [ ] REQ-F-009 잘못된 URL/존재하지 않는 트랙 코드
  - Given 형식 오류 URL 또는 존재하지 않는 코드, When 조회 시도, Then "유효하지 않은 링크입니다"/"트랙을 찾을 수 없습니다"처럼 원인이 구분된 에러 메시지를 표시하고 재입력을 유도한다.
  - 검증: 두 케이스를 각각 입력해 메시지 문구가 서로 다름을 확인.
- [ ] REQ-F-010 편집기 응답 실패/지연
  - Given 편집기 응답 지연(임계값 잠정(ASSUMPTION-007) — 미결, 확정값 아님) 또는 실패(5xx/timeout/network), When 조회 진행 중, Then loading 상태를 표시하고 실패 시 원인 구분 에러 + 재시도 버튼을 제공한다.
  - 검증: 네트워크 지연/차단을 인위 재현해 loading→error 전이 확인.
- [ ] REQ-F-011 파싱 실패
  - Given 응답 문자열이 정의 문법과 어긋남, When 파싱 시도, Then 파싱 실패를 알리고 원본 응답 일부를 접이식 디버그 영역에 노출한다.
  - 검증: 손상된 인코딩 문자열로 파싱 실패 메시지·디버그 영역 노출 확인.
- [ ] REQ-F-012 대형 트랙 렌더 성능 저하 완화
  - Given 300피스 이상인 트랙(대형 트랙 임계값, 잠정 ASSUMPTION-006), When 3D 뷰를 렌더링하면, Then
    프레임 저하 시 완화 상태로 전환되고 "대형 트랙: 일부 최적화 적용" 안내를 표시한다(구체 기법은
    tech-advisor). 참조 트랙(132피스)과 임계값(300피스) 사이인 **132~300피스는 경계 구간**으로
    정의하며, 이 구간에서는 완화 상태가 조기 발동하지 않고 정상 렌더됨을 별도로 확인한다.
  - 검증: 참조 트랙(132), 경계 구간 대표값(예: 200), 임계값 초과(300+) 세 지점 각각에서 완화 상태
    미전환/미전환/전환 여부와 fps를 측정한다.
- [ ] REQ-F-013 근거 등급 표기(정직성)
  - Given 슬로프 낙차·뱅크 전이곡선·레인 폭 등 추정치가 적용된 값, When 3D 뷰/범례에 표시하면, Then 각 값 옆에 실측/추정/미확인 등급 배지를 표기하고 표현 못한 피스는 REQ-F-008과 동일하게 드러낸다 — 실측처럼 보이게 조용히 넘기지 않는다.
  - 검증: 추정치 적용 항목 목록과 화면 배지 노출 여부를 1:1 대조.
- [ ] REQ-F-019 외부 편집기 접근 계약 준수 (Should → Must 승격, 사유: BLOCKER-001 완화 수단이 유일하게
  이 REQ에 있어 defer 가능 등급에 둘 수 없음)
  - Given 사용자가 링크를 제출한 경우, When 서버가 fetch를 수행하면, Then (a) 자동 순회·프리페치 없이 사용자 행동당 1회만 fetch하고 (b) **한 번 받아온 트랙은 캐시한다.** 층별 보장 수준이 다르므로 구분해 요구한다 — (b-1) **클라이언트 세션 인메모리 캐시는 결정적이다**: 같은 탭에서 같은 트랙 코드를 다시 제출하면 네트워크 요청이 **0회**다(새로고침 시 소멸하며 이는 저장이 아니다). (b-2) 서버/CDN 층(`s-maxage`)은 best-effort로 다른 탭·다른 사용자의 origin fetch를 줄이되 TTL 만료·POP 미스·재배포·콜드스타트 시 재fetch가 발생한다. 인프라 전체에 걸친 결정적 보장은 영속 저장소를 요구하므로 D-004(저장 없음, 재확정 D-016/D-017)에 따라 채택하지 않는다 — (c) 식별 가능한 User-Agent를 사용하고 (d) 화면에 원본 편집기(mini4wd-track-editor.pimentoso.com)로의 출처 링크를 표시한다.
  - 검증 (b-1, 결정적): 같은 탭에서 동일 코드를 2회 제출했을 때 두 번째 제출에서 **`/api/track` 요청이 0건**임을 네트워크 계측으로 확인한다. 이 항목은 실패하면 결함이다.
  - 검증 (b-2, best-effort): TTL(1시간) 내 2회 조회 시 두 번째 응답의 `x-vercel-cache`가 `HIT|STALE`인지 확인. **콜드 캐시에서의 재fetch는 결함이 아니다.**
  - 검증 (c)(d): 식별 가능한 User-Agent 전송, 화면에 출처 링크 노출. 근거: (decision-log D-002), (decision-log A-001).
- [ ] REQ-F-020 Str1(c=5) 마커 직선 처리
  - Given Str1 피스의 `c=5`(빨강+파랑 반반, 마커 색), When 해당 구간을 렌더하면, Then 고도 변화 0의
    평평한 직선으로 렌더하고 출발선 마커임을 시각적으로 표기한다(색 자체를 상승/하강 판정에 사용하지
    않는다 — REQ-F-002의 매핑은 Bri*/Ban*에 한정).
  - 검증: 참조 트랙(WS67Y2)의 Str1 c=5 구간이 인접 직선과 동일한 높이(고도 0)로 렌더되고 마커 표식이
    노출되는지 확인. 근거: measured, 픽셀 측정 2026-08-28.
- [ ] REQ-F-021 compat 플래그 처리(파싱 계약)
  - Given 편집기 응답의 `compat = parseInt(저장버전) < COMPATIBILITY_ID(26586)` 계산 결과, When
    `compat=true`이면, Then `Cor1`의 45/135/225/315° 배치에 위치 보정을 적용하고, `compat=false`이면
    보정 없이 원좌표를 사용한다.
  - 검증: compat=true 캡처 fixture(Data Strategy 절 참조)로 Cor1 배치 보정 적용 여부를 확인한다.
    참조 트랙 WS67Y2는 `compat=false`라 이 경로를 검증하지 못하므로, compat=true fixture 확보 전까지
    이 REQ는 unverifiable로 표시하고 릴리스 게이트에서 별도 관리한다.
  - 근거: measured(편집기 응답 계약, 2026-08-28).
- [ ] REQ-F-022 WebGL 미지원 환경 감지 및 대체 표현
  - Given 브라우저가 WebGL 2.0을 지원하지 않거나 컨텍스트 생성에 실패, When 3D 뷰 초기화를 시도하면,
    Then 3D 렌더링을 시도하지 않고 안내 메시지("이 브라우저는 3D 뷰를 지원하지 않습니다" 등)와 지원
    브라우저 안내를 표시하며, 가능한 경우 2D 요약(피스 수·경고 목록) 등 대체 표현을 제공한다.
  - 검증: WebGL 컨텍스트 생성을 강제로 실패시키는 테스트 환경에서 안내 메시지 노출과 3D 캔버스
    미생성을 확인. 관련: REQ-NFR-004.
- [ ] REQ-F-023 고저차 프로파일 스트립 (하단 네비게이터)
  - Given 트랙이 3D로 표시된 상태, When 사용자가 화면 하단 프로파일 스트립을 보면, Then 거리축 대비
    고저차가 한눈에 드러나고, 스트립의 임의 지점을 조작하면 3D 뷰와 추종 시점이 그 지점으로 이동한다.
  - 근거: 참조 트랙이 132피스 규모라 3D 뷰만으로는 전체 고저 구조를 파악할 수 없다 —
    코스 분석이라는 제품 목적(FEAT-007 추종 시점의 조작 수단이기도 하다)에 직결된다.
    ux-brief `Key Screen Elements Requiring FEAT`에서 필요성이 제기됐고, 사용자가 Must로 확정했다.
  - 의존: `ElevatedSegment.absoluteElevationStart/End`(누적 고도) 없이는 구현 불가.
  - 검증: 스트립의 고저 곡선이 3D 씬의 절대 고도 배열과 일치하는지 수치 대조, 스트립 조작 시
    카메라 위치가 대응 지점으로 이동하는지 확인. 소유: FEAT-012.
- [ ] REQ-F-024 텍스트 구간 목록 (대체 표현 겸 접근성 경로)
  - Given 트랙이 복원된 상태, When 사용자가 구간 목록을 보면, Then 진행 순서대로 각 구간의 유형
    (직선·코너·슬로프·뱅크·레인체인지·미지원)과 상승/하강이 텍스트로 나열되고, 항목 선택 시 3D 뷰가
    해당 구간으로 이동한다.
  - 근거: 3D 캔버스는 스크린리더·키보드 접근이 원천적으로 취약하다(REQ-NFR-003). 이 목록이 색에
    의존하지 않는 1차 정보원이며, REQ-F-022(WebGL 미지원)의 대체 표현으로도 재사용된다.
    사용자가 Must로 확정했다.
  - 검증: 키보드만으로 목록 순회·선택이 가능한지, 색 없이도 상승/하강이 구분되는지, WebGL 미지원
    환경에서 이 목록이 노출되는지 확인. 소유: FEAT-013.

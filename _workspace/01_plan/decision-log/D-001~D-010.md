## D-001 · 입력은 편집기 데이터를 우선한다 (2026-08-28, 사용자 결정)

**결과**: 이미지 CV 분석이 범위에서 빠진다. 정확도가 확률이 아니라 결정적이 된다.


## D-002 · 공유 URL을 서버가 가져온다 (2026-08-28, 사용자 결정)

사용자는 `view/XXXXXX` 링크만 붙여넣고, 서버(serverless function)가 편집기에서 트랙
데이터를 확보해 파싱한다.

**결과**: `WEB_PROFILE = vite-serverless-hybrid`. 루트 `api/`가 생긴다.
`react-vite-spa`(정적)로는 CORS 때문에 브라우저에서 직접 가져올 수 없다.

**ASSUMPTION A-001 · 외부 사이트 접근 허용** — 검증: `robots.txt`를 확인했고 **금지 규칙이
없다**(Rails 기본값, 전 항목 주석 처리). 우리 사용은 크롤링이 아니라 **사용자 행동당 1건**의
fetch다. 다만 광고로 운영되는 개인 사이트이므로 아래를 계약으로 못박는다:
- 사용자가 명시적으로 요청할 때만 fetch (자동 순회·프리페치 금지)
- 결과 캐시로 같은 트랙 재요청 시 원본을 다시 치지 않음
- 식별 가능한 User-Agent
- 화면에 원본 편집기 링크로 출처 표기

**미해소**: 사이트 운영자에게 사전 고지·동의를 받지 않았다. 서비스를 공개할 계획이면
이 항목을 다시 판단해야 한다 — 현재는 로컬/소규모 사용 전제다.


## D-003 · 슬로프/뱅크 판별에 휴리스틱을 쓰지 않는다 (2026-08-28, 조사로 대체)

사용자가 제시한 "색이 있는 트랙이 길면 슬로프, 짧으면 뱅크"는 **도면 이미지를 읽는** 규칙이었다.
데이터에는 `Bri1.label="slope"`, `Ban1.label="bank"`로 타입이 명시돼 있어 판별이 불필요하다.
도면에서 그렇게 보인 이유도 데이터가 설명한다(Ban1 폭 28px vs Bri1 54px).

색(`c`)은 **상승/하강** 표시로만 쓴다. 참조 트랙에서 슬로프 10개가 `c=2` 5개 + `c=3` 5개,
뱅크 4개가 2+2로 정확히 반씩 갈려 "올라간 만큼 내려온다"와 일치한다.

**NEEDS_DECISION N-001**: `c=2`와 `c=3` 중 어느 쪽이 빨강(상승)인지 미확인.
검증 방법: 참조 트랙 도면 이미지와 좌표를 대조하면 결정된다 — Phase 1에서 해소.

## D-007 · 슬로프 경사각 40도 (2026-08-28, 사용자 제공)

사용자가 실물 지식으로 슬로프 경사각을 **40도**로 확정했다. 근거 등급 `confirmed`(사용자 제공).

**이 값이 B-001(스케일)을 해소 방향으로 좁힌다.** 편집기 `Bri1`(slope)의 `l`은 1.62m인데,
그 전체에 40°를 균일 적용하면 상승이 **1.04m**가 된다 — 미니4WD 트랙에서 성립하지 않는다.

낙차 11cm(A-002)와 40°를 함께 놓으면 실제 경사 구간은 **빗변 17.1cm / 수평 13.1cm**이며,
이는 섹션 길이 1.62m의 **10.6%**다.

**따라서 슬로프 피스는 "전체가 40° 경사"가 아니라 평지→경사→평지 프로파일을 가진 섹션이다.**
3D 모델은 피스마다 단일 기울기를 주면 안 되고, 피스 내부의 **고도 프로파일**을 가져야 한다.
이것은 데이터 구조를 바꾸는 결정이며 Phase 2 설계에 그대로 들어간다.

**남는 미결(B-001 축소판)**: 경사 구간이 섹션 어디에 위치하는지(앞/가운데/뒤), 그리고
`Bri1`의 1.62m가 무엇의 길이인지(단일 레인 / 3레인 합 / 다른 규격). 전자는 3D 형상을,
후자는 전체 치수를 바꾼다.

**A-002(낙차 11cm) 상태 변화 없음** — 여전히 미확인이다. 40°가 확정되면서 낙차와 경사
길이가 서로를 결정하므로, **둘 중 하나만 실측되면 나머지가 따라온다.**


## D-008 · 슬로프 고도 프로파일은 사인 곡선이다 (2026-08-28, 사용자 제공)

D-007의 40°를 균일 기울기로 해석하지 않는다. 슬로프 구간의 고도는 **sin의 0°~90° 구간**
모양을 따른다:

```
h(x) = H · sin( (π/2) · x/L )        x ∈ [0, L]
```

바닥에서 가장 가파르고 마루에서 기울기 0으로 평평해진다.

**이 모델이 데이터의 5:5 대칭을 설명한다.** 상승 피스(sin 0→90°)와 하강 피스(sin 90→180°)가
이어지면 마루에서 양쪽 기울기가 모두 0으로 만나 **꺾임 없는 언덕 하나**가 된다. 참조 트랙에서
슬로프가 `c=2` 5개 + `c=3` 5개로 정확히 갈리는 것이 이 짝짓기와 일치한다.

**유도되는 관계** — 최대 기울기는 x=0에서 `H·π/(2L)`이므로, 최대 경사각 40°이면:

| 항목 | 값 |
|---|---|
| `H/L` | 0.5342 |
| 평균 경사각 | 28.1° |
| 낙차 11cm일 때 경사 구간 길이 | **20.6 cm** |
| `Bri1` 전체(1.62m)를 경사로 볼 때 상승 | 86.5 cm ← 불가능 |

선형 모델과 비교하면 같은 낙차에 수평 거리가 13.1cm → 20.6cm로 늘어난다.

**결과**: 3D 모델은 피스에 스칼라 기울기가 아니라 **매개변수 곡선**을 부여한다. 트랙 추종
시점의 카메라 피치도 이 곡선의 미분에서 나온다 — 별도 모델이 필요 없다.

**NEEDS_DECISION N-003**: 40°가 이 곡선의 **최대 기울기**(구간 시작점)라는 해석이 맞는지.
평균 경사각으로 읽으면 최대가 훨씬 가팔라진다(약 53°). 위 표는 최대 기울기 해석 기준이다.

**B-001은 여전히 열려 있다** — 경사 구간(20.6cm 추정)이 `Bri1` 섹션(1.62m) 안에서 어디에
놓이는지, 그리고 1.62m가 무엇의 길이인지는 미해결이다.


## D-009 · 정정: 프로파일은 양 끝 기울기가 0인 S곡선이다 (2026-08-28, 사용자 정정)

D-008의 "sin 0~90° 구간"을 **양 끝 0°**로 정정한다. 1/4 사인은 시작점이 가장 가팔라
평지와 만나는 지점에 꺾임이 생긴다. 실제는 시작과 끝이 모두 기울기 0이다:

```
h(x) = (H/2) · ( 1 − cos(π · x/L) )        x ∈ [0, L]
h'(x) = (H/2)(π/L) · sin(π · x/L)          최대는 중앙 x = L/2
```

**수치는 바뀌지 않는다.** 두 모델의 최대 기울기가 공통으로 `H·π/(2L)`이라 `H/L = 0.5342`,
평균 경사 28.1°, 낙차 11cm → 경사 구간 20.6cm가 그대로 성립한다. 바뀌는 것은 **모양**이다.

| 위치 | 높이 | 기울기 |
|---|---|---|
| 0% | 0.00 cm | 0.0° |
| 25% | 1.61 cm | 30.7° |
| 50% | 5.50 cm | **40.0°** |
| 75% | 9.39 cm | 30.7° |
| 100% | 11.00 cm | 0.0° |

**설계 결과 3가지**
1. 슬로프 피스는 양 끝에서 평지와 **접선 연속**이다 — 이음매에 꺾임이 없다.
   피스 경계에서 기울기를 맞추는 별도 보정 로직이 필요 없다.
2. 상승 피스 하나가 평지→평지로 `H`만큼 올리는 **완결된 계단**이다. 참조 트랙의 상승 5개 ·
   하강 5개는 5칸 올라갔다 5칸 내려오는 구성이며 합이 0이다.
3. 트랙 추종 카메라의 피치는 `h'(x)`에서 직접 나온다 — 최대 40°, 양 끝 0°.

**N-003 해소**: 40°는 이 곡선의 **최대 기울기**이며 구간 중앙에 위치한다.

**B-001 여전히 열림**: 경사 구간(20.6cm)이 `Bri1` 섹션(1.62m) 안 어디에 놓이는지,
1.62m가 무엇의 길이인지는 미해결.


## D-010 · 뱅크 프로파일은 로그 곡선이다 (2026-08-28, 사용자 제공)

뱅크 구간의 프로파일은 로그 그래프 모양이다 — **처음이 가장 가파르고 뒤로 갈수록 완만**해지며
위로 볼록하다(concave down). 슬로프의 S곡선과 모양이 반대다.

```
f(x) = log(1 + k·x/L) / log(1 + k)      f(0)=0, f(L)=1, 최대 기울기는 x=0
```

| 진행률 | 로그 | 슬로프 S곡선 |
|---|---|---|
| 12.5% | 32.7% | 3.8% |
| 25% | 51.2% | 14.6% |
| 50% | 74.0% | 50.0% |
| 75% | 88.9% | 85.4% |

로그는 구간의 1/4에서 이미 절반을 넘어선다. S곡선은 절반 지점에서 정확히 절반이다.

**NEEDS_DECISION N-004 · 이 로그 곡선이 무엇의 프로파일인가**

뱅크 피스에는 프로파일이 둘 있을 수 있다:
- **고도** — 데이터에서 `Ban1`이 `c=2` 2개 + `c=3` 2개로 **상승/하강 색을 갖는다.**
  슬로프와 같은 색 체계이므로 뱅크도 고도가 변한다는 뜻이다.
- **롤(옆 기울기)** — 뱅크의 정의적 요소. 최대 20°(D-005에서 공식 확인).

로그가 둘 중 어느 쪽인지, 혹은 둘 다인지 확정해야 3D 형상이 정해진다. 미확정 상태로
구현하면 뱅크가 실물과 다른 모양이 된다.

**형상 정합성 관찰**: 슬로프는 양 끝 기울기 0으로 평지와 접선 연속인데(D-009), 로그는
시작점 기울기가 최대라 진입에 꺾임이 생긴다. 뱅크 진입은 원래 그런 것인지, 아니면
로그가 롤 각도에만 적용되고 고도는 다른 곡선인지가 위 결정과 함께 풀린다.

## 새로 확보한 증거 (이 지시서의 근거)

**색 인덱스 (measured, 픽셀 측정 2026-08-28)** — `plan-review` #2 지적이 옳았다.

| 피스.색 | 평균 RGB | 색 |
|---|---|---|
| `Bri1.c2` · `Ban1.c2` | (0,78,143) | 파랑 |
| `Bri1.c3` · `Ban1.c3` | (173,10,9) | 빨강 |
| `Bri1.c0` | (48,162,121) | 청록 |
| `Str1.c5` | 빨강+파랑 반반 | 마커 |
| `Str1.c6` | (242,171,0) | 주황 |

- **`c=3` = 상승, `c=2` = 하강** (사용자 규칙 "빨강=상승"과 결합). 등급 `measured`. **N-001 닫힘.**
- **`c`는 팔레트 인덱스이지 상승/하강 플래그가 아니다.** 규칙은 **"고도 변화 피스(`Bri*`·`Ban*`)에
  한해 빨강 변형=상승, 파랑 변형=하강"**으로 좁혀 서술한다.
- **`Str1 c=5`는 마커 직선**(출발선 표식). 고도 변화 0. 평평한 직선으로 렌더하고 표식만 표기.

**데이터 취득 계약 (measured)** — `GET /load/{CODE}.js` + 헤더 `X-Requested-With: XMLHttpRequest`.
헤더 없으면 422. 응답에 `var text = '<피스문자열>'`과 `compat` 플래그.
`compat = parseInt(<저장버전>) < COMPATIBILITY_ID(26586)`. **true이면 `Cor1`의 45/135/225/315°
배치에 위치 보정이 붙는다.** WS67Y2는 `compat=false`. **headless 브라우저는 불필요하다.**

**스케일 (unknown — 닫히지 않았다)** — 편집기 `l` 합(190.84)이 편집기 자신의 `track_length`와
같다는 것은 **자기참조 일치**이며 단위가 미터라는 증명이 아니다. `Str1`의 `l`=1.62가 단일
레인인지 3레인 합인지 미확정(B-001).

## 전역 규칙 (모든 담당자 공통)

**R1 — 근거 등급을 값마다 붙인다.** `measured`(직접 측정) / `confirmed`(사용자 제공) /
`inferred`(간접 추론) / `unknown`. 선언만 하고 본문에서 섞지 마라.

**R2 — 절대 단위 표기 금지 (B-001이 닫힐 때까지).** 총 길이·피스 길이·낙차를 "190.84 m"처럼
**절대 단위로 화면에 내보내지 않는다.** 대신 편집기 원단위(`l` 단위) 또는 상대 비율로 표기하고
등급 배지를 붙인다. 문서에서 수치를 인용할 때도 `190.84 (편집기 l 단위, unknown)`처럼 적는다.

**R3 — ID 체계 통일.** `decision-log`의 `A-00x`/`N-00x`와 `requirements`의 `ASSUMPTION-00x`가
같은 꼴로 다른 대상을 가리켜 충돌한다(#17). **`requirements.md`의 `ASSUMPTION-NNN`/`BLOCKER-NNN`을
정본으로 삼고**, decision-log의 A/N 번호를 인용할 때는 항상 `(decision-log A-002)`처럼
출처를 병기한다.

**R4 — 미결과 확정을 동시에 쓰지 마라(#10, #13).** NEEDS_DECISION으로 남긴 항목의 값을
같은 문서 다른 절에서 단정하지 않는다. 잠정값이 필요하면 `잠정(ND-x 미결)`로 표기한다.

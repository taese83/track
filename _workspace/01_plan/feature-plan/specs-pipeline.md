# Feature Plan — 동작 명세·테스트 (pipeline)

### FEAT-001 — URL 입력 및 서버사이드 fetch

**동작 명세**: 사용자가 붙여넣은 공유 링크를 serverless function이 검증·조회하고, 형식 오류·존재하지 않는 코드·응답 지연·서버 실패를 원인별로 구분해 표시하며 동일 코드는 캐시로 재사용한다.

- TC-001-1: Given 유효한 view/XXXXXX 형식 링크, When 사용자가 제출하면, Then serverless function이 fetch에 성공하고 원본 응답이 파싱 단계로 전달된다.
- TC-001-2: Given 형식이 view/XXXXXX와 다른 잘못된 URL, When 제출하면, Then "유효하지 않은 링크입니다" 메시지가 표시되고 재입력이 유도된다.
- TC-001-3: Given 형식은 맞지만 존재하지 않는 트랙 코드, When 조회하면, Then "트랙을 찾을 수 없습니다" 메시지가 표시된다.
- TC-001-4: Given 편집기 응답이 임계값(잠정, ASSUMPTION-007)을 넘겨 지연되는 상태, When 조회가 진행 중이면, Then loading 인디케이터에 "시간이 걸리고 있어요" 안내가 추가된다.
- TC-001-5: Given 편집기 서버가 5xx/timeout/network 오류를 반환, When 조회를 시도하면, Then 원인이 구분된 에러 메시지와 재시도 버튼이 표시된다.
- TC-001-6: Given 같은 탭에서 이미 한 번 불러온 트랙 코드, When 같은 코드를 다시 제출하면, Then 클라이언트 세션 캐시에서 즉시 복원되고 `/api/track` 네트워크 요청이 0건이다.
- TC-001-8: Given 동일 트랙 코드를 캐시 TTL(s-maxage=3600) 내에 다른 탭에서 조회, When 제출하면, Then 응답의 `x-vercel-cache` 헤더가 HIT 또는 STALE이다. 콜드 캐시에서의 재fetch는 결함으로 보지 않는다.
- TC-001-7: Given 3D 표시 화면이 로드된 상태, When 화면을 확인하면, Then 원본 편집기(mini4wd-track-editor.pimentoso.com)로의 출처 링크가 상시 노출된다(PAGE-000 공통 책임).


### FEAT-002 — 트랙 문자열 파싱 → 피스 목록

**동작 명세**: "클래스;x;y;각도;색"을 `#`로 이은 원본 문자열을 개별 피스 객체 배열로 변환하고, 문법이 어긋나면 렌더를 진행하지 않고 파싱 실패를 알린다. 응답에 함께 내려오는 compat 플래그(parseInt(저장버전) < COMPATIBILITY_ID(26586), REQ-F-021)도 함께 파싱해 각 피스에 전달한다. compat=true면 Cor1의 45/135/225/315° 배치에 위치 보정이 필요함을 표시하는 메타데이터를 부여한다. 참조 트랙 WS67Y2는 compat=false이므로 이 보정 경로는 WS67Y2 데이터로는 검증할 수 없고 별도 compat=true fixture가 필요하다.

- TC-002-1: Given 정상 문법의 참조 트랙(WS67Y2) 원본 문자열, When 파싱을 수행하면, Then 132개의 피스 객체(class, x, y, angle, color)가 산출된다.
- TC-002-2: Given 정의 문법과 어긋난 손상 문자열, When 파싱을 시도하면, Then 파싱 실패 메시지가 표시되고 원본 응답 일부가 접이식 디버그 영역에 노출된다.
- TC-002-3: Given 피스가 0개이거나 빈 문자열인 응답, When 파싱을 시도하면, Then 파싱 실패로 처리되고 디버그 영역에 원본이 노출된다.
- TC-002-4: Given compat=false인 참조 트랙(WS67Y2) 응답, When 파싱하면, Then compat 플래그가 false로 기록되고 Cor1 위치 보정 메타데이터가 부여되지 않는다.
- TC-002-5: Given compat=true fixture(요구사항 fixture 7종 중 7번째, WS67Y2로는 검증 불가), When 파싱하면, Then compat 플래그가 true로 기록되고 45/135/225/315° 위치의 Cor1에 보정 메타데이터가 부여되어 FEAT-006(배치)이 소비할 수 있다. 이 TC는 WS67Y2 데이터로는 실행 불가하며 별도 compat=true fixture가 확보되기 전까지 skip 상태로 관리한다.


### FEAT-003 — 진행 순서 복원 (끝점 매칭)

**동작 명세**: 순서 없는 피스 배치에서 각 피스의 vertex1/vertex2에 회전·이동을 적용해 매칭하고, START(Str2)부터 시작하는 결정적 순서를 산출한다. 네 가지가 함께 필요하다(D-038·D-039):
① **출발 방향은 START 피스의 화살표**(local +x 정점 쪽)로 고정한다 — "더 멀리 가는 쪽"을 고르면 폐곡선이 끊겨 있을 때 항상 거꾸로 돈다.
② **매달린 끝이 정확히 둘이면 서로 잇는다** — 이을 곳이 하나뿐이라 모호함이 없다.
③ **분기 후보는 좌표 정확 일치를 1순위로** 고르고, 같은 무리(0.02cm 이내) 안에서만 접선 연속성으로 가른다. 편집기는 실제로 물린 이음새의 좌표를 소수점까지 똑같이 저장하므로, 느슨한 허용오차로 뭉개면 판별 신호가 사라진다.
④ **막히면 되돌아간다** — 방향만 보고 전진하면 입체교차에서 갇힌다.
START가 0개이거나 2개 이상인 비정상 입력도 렌더를 막지 않는 범위에서 결정적으로 처리한다.

- TC-003-1: Given 파싱된 참조 트랙 132개 피스, When 끝점 매칭을 수행하면, Then Str2에서 시작하는 132개 순서 배열이 산출되고 **마지막 피스가 출발점으로 돌아와 폐곡선이 닫힌다**.
- TC-003-2: Given 동일 트랙 코드로 3회 반복 조회, When 매번 순서 복원을 수행하면, Then 3회 모두 동일한 순서 배열이 산출된다.
- TC-003-3: Given 네 끝점이 한 점에 모이는 입체교차, When 매칭을 수행하면, Then **좌표가 소수점까지 일치하는 쌍**을 이음새로 선택한다(참조 트랙 실측: 정확 일치 0.00cm vs 다른 무리 0.06cm). 접선 연속성은 같은 무리 안에서만 쓴다 — 무리를 뭉개면 접선으로는 틀린 쪽이 더 직진으로 나와 복구가 불가능하다.
- TC-003-6: Given START 피스, When 순서 복원을 시작하면, Then 화살표가 가리키는 쪽(local +x 정점)으로 출발한다.
- TC-003-4: Given Str2(START) 피스가 0개인 파싱된 피스 배열, When 순서 복원을 시도하면, Then 순서 복원이 실패로 처리되고 "시작 지점(START)을 찾을 수 없습니다" 메시지와 함께 FEAT-002의 파싱 실패와 동일한 처리 경로(디버그 영역 노출)를 따르며 3D 렌더는 시도하지 않는다. 이 케이스에 대응하는 fixture는 requirements.md의 6종 fixture 중 "START 부재"다.
- TC-003-5: Given Str2가 2개 이상 존재하는 파싱된 피스 배열, When 순서 복원을 시도하면, Then 결정적 규칙(배열 내 최초 등장 피스)으로 시작점 하나를 선택하고 선택 근거를 디버그 영역에 기록하며, 나머지 Str2는 마커 직선(REQ-F-020)으로 일반 처리된다. 이 케이스의 전용 fixture는 아직 확보되지 않았다 — NEEDS_DECISION(requirements-analyst와 fixture 조율 필요).


### FEAT-004 — 폐곡선 검증 및 부분 실패 노출

**동작 명세**: 복원된 순서가 START로 되돌아오는 XY 폐곡선을 이루는지 검증한다. 아니면 연결 가능한 구간까지만 정상 렌더하고 끊긴 지점을 시각적으로 표시하며 화면 전체 렌더링을 중단하지 않는다. XY 폐곡선 검증과 별도로 Z(고도) 폐합도 검증한다 — 경로를 따라 누적된 상승/하강 고도의 합이 START 지점으로 되돌아왔을 때 허용오차 이내로 상쇄되는지 확인한다. XY는 닫혀 있어도 상승/하강 피스가 불균형하면 START에서 수직 불연속이 발생할 수 있으므로 이를 XY 폐곡선 검증과 별개의 상태(`isZClosed`)로 다루고, 억지로 보정해 맞추지 않는다.

- TC-004-1: Given 정상 폐곡선을 이루는 참조 트랙, When 폐곡선 검증을 수행하면, Then 검증 통과로 판정되고 경고 배너는 노출되지 않는다.
- TC-004-2: Given 끝점이 의도적으로 어긋난 비폐곡선 테스트 데이터, When 파싱·순서복원이 완료되면, Then 연결 가능한 구간은 정상 렌더되고 끊긴 지점은 강조색/아이콘과 함께 "일부 구간의 순서를 확정하지 못해 해당 구간은 회색으로 표시됩니다" 경고 배너가 상시 노출되며 렌더링은 중단되지 않는다.
- TC-004-3: Given 부분 실패 상태로 렌더된 화면, When 사용자가 3D 뷰를 회전·확대하면, Then 실패 구간은 회색·점선 표시를 유지하고 정상 구간의 조작은 그대로 동작한다.
- TC-004-4: Given 상승 피스와 하강 피스의 누적 고도 합이 START에서 상쇄되는 참조 트랙, When 고도 폐합(Z closure) 검증을 수행하면, Then 폐합 오차가 허용오차 이내(값 자체는 ASSUMPTION-001 등급에 종속) 로 판정되고 별도 경고가 노출되지 않는다.
- TC-004-5: Given XY는 폐곡선이지만 상승/하강 누적 고도가 불균형한 테스트 데이터, When Z 폐합 검증을 수행하면, Then START 지점에 수직 불연속 경고 아이콘과 "고도가 시작 지점과 어긋납니다" 배너가 노출되고, 3D 렌더는 계산된 절대 고도값을 그대로 표시하며(강제 보정 없음) 렌더링은 중단되지 않는다. 이 케이스 전용 "고도 불균형" fixture는 아직 확보되지 않았다 — NEEDS_DECISION.
- TC-004-6: Given 고도 폐합 실패 상태, When FEAT-012(프로파일 스트립)를 표시하면, Then START/END 지점의 절대 고도 차이가 스트립 그래프 양 끝단에서 수직 불연속으로 드러난다.


### FEAT-005 — 고도 프로파일 생성 (슬로프 S곡선·뱅크 전이곡선+기운 평면)

**동작 명세**: 복원된 경로의 각 피스에 타입별 고도 프로파일 함수를 적용해 피스 내부를 곡면 세그먼트로 변환한다. 고도는 **현(chord) 규칙**으로 정한다(D-022, 사용자 지정 렌더 규칙 — 실물 실측 아님): 피스의 시작점과 끝점을 이은 직선이 슬로프는 **20°**(D-025 → D-042), 뱅크는 **20°**(D-042에서 공식 실측값으로 복귀)를 이루도록 `H = 진행축 px × sin(각도)`로 총 상승량을 계산한다(D-023 — 진행축 px는 차가 달린 거리, 즉 빗변이다). 상승 뱅크와 하강 뱅크 **사이 구간**은 **하나의 20° 기운 평면(판)** 위에 놓이고, 트랙이 그 판 위를 돌면서 올라갔다 내려온다(D-029). **뱅크 피스 자체는 판이 아니라 전이 곡선**이다 — 평지와 판 양쪽에 접하며 **기울기가 0에서 판 기울기까지 단조 증가**한다(D-040 + D-041). 단조 조건 때문에 전이는 판 연장선보다 낮게 끝나므로 판 전체를 그 차이(`lift`)만큼 내려놓아야 이음새가 붙는다 — C0·C1 연속과 단조 기울기를 동시에 만족하는 유일한 방법이다(D-041). 기울기 축은 구간 진입점과 진출점을 잇는 선이라 두 점 높이가 같고 폐곡선이 닫힌다. 뱅크 구간은 색과 무관하게 **위로 솟는다**(D-031이 두 방향을 렌더해 비교한 뒤 확정한 그림이며, 본문의 "아래로 파임"은 투영 부호가 틀린 상태의 규약으로 쓴 표현이었다 — D-045가 정정). 웨이브(Chi*)는 고도 변화가 없고 진행 방향 기준 **왼쪽으로 5cm 곡면 돌출**하며 양 끝이 직선이다(D-032). 레인체인지(Lan*)는 고도 변화가 없고 세 레인이 **한 칸씩 순환**(0→1, 1→2, 2→0)하며 교차한다 — 바깥 레인이 나머지 둘을 가로지른다(D-033, 공식 API의 order:[1,2,3] 근거). 레인은 선이 아니라 **면**으로 그린다 — 레인마다 12cm 폭을 가지며 전체 트랙 폭은 36cm다(D-034). 레인체인지에서 두 칸 건너뛰는 레인(3→1)은 나머지 둘 위로 넘어가는 **육교**이며 높이 8cm의 sin² 곡선으로 올라갔다 내려온다(D-035). 뱅크가 연속이면 기울기가 누적되나(+20°/−20°) **다단 기하는 미구현**이다(D-030). 롤(좌우 눕힘)은 쓰지 않는다 — 노면은 좌우로 평평하다. 슬로프의 **모양**은 양 끝 기울기 0의 S곡선 `h(x)=H/2·(1−cos(πx/L))`이다. 판은 평면이라 프로파일 함수를 쓰지 않고, 뱅크 피스만 전이 곡선을 쓴다(D-029가 로그 곡선 모델을, D-041이 3차 곡선 구현을 대체했다). 모양은 총 상승량을 바꾸지 않는다. S곡선이 양 끝 0°로 같은 높이를 내려면 중앙이 **약 52.8°**가 되는데 이는 모양의 수학적 귀결이지 지정값이 아니다. 이음매 접선 연속을 보장한다. 색상 규칙은 팔레트 인덱스 기준으로 좁혀 적용한다 — 고도 변화 피스(Bri*, Ban*)에 한해 c=3(빨강 계열)=상승, c=2(파랑 계열)=하강이다(measured, decision-log N-001 해소; `c`는 방향 플래그가 아니라 팔레트 인덱스이므로 `Bri1.c0`=청록, `Str1.c6`=주황처럼 다른 의미로도 쓰인다). Str1의 c=5(마커 직선, REQ-F-020)는 고도 변화가 없는 출발선 표식이며 상승/하강 판정에서 제외하고 평평한 flat 프로파일로 렌더한다.

- TC-005-1: Given Bri1(slope) 피스와 앞뒤 평지 피스, When 고도 프로파일을 생성하면, Then 총 상승량이 진행축 px × sin20°와 일치하고 h(x)=H/2·(1−cos(πx/L)) 곡면이 생성되며 양 끝 접선 기울기가 0으로 앞뒤 평지와 매끄럽게 이어진다(이음매 접선각 오차 ±1° 이내, REQ-F-002).
- TC-005-6: Given Ban1(bank) 피스, When 고도 프로파일을 생성하면, Then 그 피스 안에서 진행 방향 기울기가 **단조 증가**하여(감소 구간 0개) 판 기울기를 넘지 않고, 시작 기울기가 0(평지와 접선), 끝 기울기가 판 기울기와 같다(D-041).
- TC-005-2: Given 상승 뱅크와 하강 뱅크로 둘러싸인 구간, When 고도를 생성하면, Then **뱅크 피스를 뺀 판 구간**의 모든 점이 하나의 평면 위에 놓이고(적합 잔차 ≤0.01cm) 평면 기울기가 20°이며 구간 진입·진출 높이가 같다(REQ-F-002). **판정 대상이 판 구간인 이유**: 뱅크 피스는 전이 곡선이라 판을 벗어난다(D-041). 구간 전체로 재면 잔차 2.93cm이나 판 구간만 재면 0.0000cm다.
- TC-005-3: Given 상승색과 하강색이 짝지어진 슬로프 쌍(참조 트랙 상승c=3/하강c=2), When 프로파일을 생성하면, Then 마루에서 두 곡선의 기울기가 모두 0으로 만나 꺾임 없는 언덕 하나가 형성된다.

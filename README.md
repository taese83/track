# 미니4WD 트랙 3D 뷰어

미니4WD 트랙 도면(편집기 공유 코드)을 받아 **3레인 3D 형상**으로 그리는 웹 서비스.
지금은 **설계 프리뷰 단계**다 — 의존성 0의 프로토타입으로 동작을 검증하고 있고,
실제 구현(three.js)은 아직 시작하지 않았다.

## 실행

프리뷰는 정적 파일이라 아무 정적 서버나 된다.

```bash
npx serve _workspace/02_design/preview -l 4488
```

브라우저에서 `http://localhost:4488` → 하단 개발 패널의 **"실 트랙 WS67Y2"** 버튼을 누르면
실제 트랙 132피스가 그려진다.

조작: 드래그 = 회전(좌우 z축 / 상하 x축) · Q·E = y축 · 휠 = 확대 · 방향키 = 회전

## 지금 상태

| 항목 | 값 |
|---|---|
| 순서 복원 | **132 / 132**, 폐곡선 닫힘, 화살표 방향 |
| 트랙 폭 | 36 cm (레인 3개 × 12cm), 레인마다 독립 면 |
| 슬로프 | S곡선, 현 22°, 피스당 20.2 cm |
| 뱅크 | 전이 곡선(평지·직선 양쪽에 접함) + 18° 기운 평판 |
| 웨이브 | 고도 변화 없음, 평면상 오른쪽 5 cm 곡면 돌출 |
| 레인체인지 | 1→2, 2→3, 3→1 순환 · 3→1이 육교(+8 cm) |
| 고도 불연속 | 0 건 |

## 다음에 할 것

1. **뱅크 이후 구간이 직선이 아니다** — 사용자 도면은 전이 뒤가 직선이지만 현재는
   기울어진 평판 위를 돌아 완만한 곡선이 된다. 사다리꼴(직선 → 둥근 마루 → 직선)이
   대안. `decision-log/D-037~D-050.md` D-040 참조.
2. **육교 방향 미확인** — 레인체인지 3→1 레인이 `+8cm`(위로). 주행 방향이 화살표 쪽으로
   바뀌면서 다른 요소들은 모두 뒤집혔는데 이것만 확인을 못 받았다.
3. **BLOCKER-002** — 뱅크가 연속이면 기울기가 누적되어야 하나(상승 2연속 = 40°) 다단
   기하가 미구현. 참조 트랙에 사례가 없어 검증 불가.
4. **Phase 2 마무리** — read-only `design-reviewer` 실행 후 Phase 3(구현) 체크포인트.

## 구조

```
_workspace/
  00_source/          편집기 데이터 모델·피스 실측(픽셀 분석)·공식 API
  01_plan/            요구사항·UX·기능 목록·결정 로그
  02_design/          디자인 시스템·레이아웃·API 스키마·컴포넌트
    preview/          ← 실행되는 프로토타입
      geom3d.js       3레인 3D 기하 생성과 투영 (의존성 0)
      store.js        파서·순서 복원·도메인 상태
      app.js          렌더·조작
```

**읽는 순서**: `01_plan/decision-log/INDEX.md` → 해당 결정 파일.
결정이 여러 번 뒤집힌 항목이 많으므로(뱅크는 다섯 번) **가장 큰 번호가 정본**이고,
철회된 것은 헤더에 `[철회]`/`[대체]`가 붙어 있다.

## 근거 등급

문서의 값에는 등급이 붙어 있다. 섞지 말 것.

- `measured` — 편집기 이미지 픽셀 측정이나 공식 API로 확인한 값
- `confirmed` — **사용자가 지정한 렌더 규칙.** 실물 실측이 아니다
  (슬로프 22°, 뱅크 18°, 육교 8cm 등이 여기 해당)
